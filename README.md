## 🧾 Task Service

**Task Service** — микросервис управления задачами в составе микросервисной платформы форума.
Сервис отвечает за создание, обновление и обработку задач, а также за асинхронную фоновую обработку с использованием очередей сообщений. Взаимодействие с другими сервисами осуществляется через **Kafka**, а выполнение длительных операций выносится в **Celery**.

Task Service является частью проекта **[Microservices_Site](https://github.com/Weit145/microservices_site)**.

### 🔧 Зона ответственности

* **Асинхронная отправка электронных писем** с использованием Celery и RabbitMQ.
* **Отправка писем для подтверждения регистрации**: основная задача сервиса. Обрабатывает событие регистрации, генерирует HTML-письмо из шаблона и отправляет его новому пользователю.
* **Инициирование периодических проверок**: ставит в очередь задачу, которая отправляет событие в Kafka для проверки неактивных или не верифицированных пользователей.

### 🧩 Взаимодействие в системе

* **Потребляет события из Kafka:**
  * `auth`: Получает данные о новом пользователе (email, имя, токен) от `auth-service`, чтобы инициировать отправку письма для подтверждения регистрации.

* **Публикует события в Kafka:**
  * `check_verified`: Периодически отправляет событие, которое потребляется `auth-service` для поиска и удаления не верифицированных пользователей.

* **Использует RabbitMQ** как очередь задач для **Celery**, чтобы гарантировать асинхронное и надежное выполнение отправки email.

* **Взаимодействует с внешним SMTP-сервером** (например, `smtp.gmail.com`) для фактической отправки писем.

* Не имеет gRPC API и не принимает прямых HTTP-запросов. Является полностью фоновым сервисом.


### 🛡️ Безопасность и примечания

* Вся логика постановки и обработки задач централизована в Task Service.
* Сервис масштабируется независимо от других компонентов системы.
